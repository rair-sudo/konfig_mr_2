# Сравнение с Maven dependency:tree

Проверка выполнена 20 ноября 2026 года. Для независимого эталона использованы
Apache Maven 3.9.11, Java 21 и Maven Dependency Plugin 3.8.1. В каждом POM из
`examples/comparison` объявлен один выбранный пакет. Выполнялась цель
`dependency:tree` с `-Dscope=runtime -DoutputType=text`. Все три запуска Maven
завершились успешно. Maven применялся только для сравнения, а не внутри
разработанной программы.

Программа отдельно запустилась с `examples/junit.csv`,
`examples/commons_text.csv` и `examples/slf4j_api.csv`. Ни один фильтр не
задан. Сравнивались вершины и направленные рёбра от указанного пакета к его
зависимостям. Искусственный корень проекта из POM сравнения и его ребро к
выбранному пакету из сопоставления исключены; суффиксы типа `jar` и scope
Maven не включались в трёхчастные координаты. Текст полученных D2 проверен
компиляцией установленным D2.

## Как повторить в Windows

Нужны Python, доступ к сети и отдельно установленный Apache Maven с `mvn` в
`PATH`. Выполните из корня проекта:

```bat
scripts\test_maven.bat
scripts\compare_maven.bat
```

Первый скрипт формирует D2 и SVG нашей программой. Второй отдельно выводит
деревья Maven для тех же пакетов. В деревьях Maven необходимо сравнивать
поддерево запрошенного пакета без искусственного корневого проекта.

## Возможные расхождения на других пакетах

В этих трёх примерах различий нет; совпадение не означает полной совместимости
с Maven. Наш анализатор не разрешает импорт BOM, профили, версии-диапазоны,
`LATEST`/`RELEASE` и timestamped SNAPSHOT через metadata. Он не выполняет
конфликтное разрешение версий Maven, не применяет транзитивные `exclusions`
и не распространяет scope вдоль пути. Он пропускает `test`, `provided`,
`system`, `import` и `optional`, а также выводит координаты без `type` и
`classifier`. Из-за этого другие графы могут содержать отличающиеся узлы или
рёбра либо завершиться с понятной ошибкой вместо вычисления результата.
